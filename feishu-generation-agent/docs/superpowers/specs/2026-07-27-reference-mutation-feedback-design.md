# 参考素材替换与删除交互修复设计

## 已确认的根因

- 远程客户端已成功发送删除请求，服务端返回 `200 OK`，对应素材也已从计划中移除。
  当前页面没有就近展示删除中或删除成功状态，用户容易判断为按钮无响应。
- 替换按钮通过 JavaScript 调用隐藏文件输入框的 `click()` 打开文件选择器。
  实际日志中没有替换上传请求，说明流程停在客户端选择文件之前。
- 错误目前只显示在页面顶部。用户操作参考素材时通常位于页面中下部，
  即使请求被前端规则阻止，也难以看到原因。

## 交互方案

### 替换

- 每条参考素材使用浏览器原生 `label` 与文件输入框关联，由浏览器处理文件选择，
  不再调用隐藏输入框的 JavaScript `click()`。
- 文件输入框保持视觉紧凑，但不能使用 `display: none`；采用可访问的视觉隐藏方式。
- 用户选择文件后自动开始替换，并在当前素材行显示：
  `已选择文件`、`正在替换…`、`替换成功`或具体错误。
- 替换期间禁用该行替换和删除按钮，避免重复请求。

### 删除

- 点击后立即把按钮改为“删除中…”并禁用该行操作。
- 服务端成功后强制刷新审批计划，素材行消失，并在参考素材区展示“已删除并重新编号”。
- 服务端失败时恢复按钮并在当前素材行展示具体错误。
- 删除仍沿用现有接口，不新增二次确认步骤。

### 顺序

- 删除后剩余参考素材必须按当前顺序重新编号为连续的 `1…N`。
- 提示词中的 `@图片N`、`@视频N`、`@音频N`引用继续由服务端同步重映射。
- 替换保留被替换素材在当前任务中的位置和用途。

## 状态边界

- 行内交互状态只保存在当前浏览器页面，不写入审批计划。
- 审批计划、参考素材及提示词仍以服务端返回结果为准。
- 当前任务存在未保存的提示词或选择修改时，参考素材操作仍可被现有规则阻止，
  但阻止原因必须显示在当前参考素材区。
- 多用户隔离、Portal 代理方式和后端接口保持不变。

## 测试

- 前端测试验证替换使用原生关联控件，不再调用隐藏输入框 `.click()`。
- 前端测试验证选择、上传、成功和失败状态可见。
- 前端测试验证删除时立即进入忙碌状态，成功与失败都有就近反馈。
- 后端测试验证删除中间素材后顺序变为连续 `1…N`，提示词引用同步调整。
- Portal 代理测试继续覆盖 `POST`、`PATCH`、`DELETE`。
- 使用远程 Portal 页面完成一次替换和一次删除验收；使用测试运行或可恢复素材，
  不触发生成任务。

## 非目标

- 不改变 Seedance 提交方式。
- 不改变参考模式规则。
- 不增加客户端依赖或构建工具链。
- 不自动批准或启动生成任务。
