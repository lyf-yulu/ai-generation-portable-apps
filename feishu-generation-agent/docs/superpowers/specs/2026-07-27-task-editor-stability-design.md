# 审批编辑框稳定性修复设计

## 问题

审批页面每秒轮询运行状态。当前每次轮询都会重新创建整个任务编辑区，
导致提示词和负面约束文本框的滚动位置、焦点及用户拖拽高度不断被重置。
同时两个文本框的默认高度偏小，不便于编辑较长内容。

## 方案

保留每秒状态轮询，但将运行状态渲染与任务编辑区渲染分开：

- 每次轮询继续更新节点、耗时、状态、交付信息等非编辑区域。
- 比较轮询前后的服务端审批计划标识。
- 只有首次加载、服务端审批计划确实变化或用户明确要求刷新时，才重新创建任务编辑区。
- 相同审批计划的普通轮询不替换现有文本框，从而保留焦点、滚动位置和拖拽高度。
- 提示词文本框设置更大的默认最小高度；负面约束文本框设置适中的默认最小高度。
- 两个文本框均保留内部纵向滚动和浏览器原生纵向拖拽。

## 数据与交互

用户输入仍通过现有 `ReviewState.patchTask` 写入本地草稿，审批时沿用现有提交快照。
本次修改不改变后端接口、审批数据格式、轮询频率或多用户隔离逻辑。

当参考素材、任务内容或文档版本在服务端发生变化时，现有冲突检测仍优先：
有本地修改则提示冲突，不覆盖用户草稿；没有本地修改则刷新任务编辑区。

## 测试

- 前端行为测试：相同计划连续轮询后，任务编辑框节点保持不变。
- 前端行为测试：服务端计划变化后，任务编辑区会重新渲染。
- 样式测试：提示词和负面约束具有独立的最小高度、`overflow-y: auto`
  和 `resize: vertical`。
- 运行全部前端与后端回归测试。

## 非目标

- 不改变提示词内容或规划逻辑。
- 不停止待审批阶段的状态轮询。
- 不引入前端框架或构建依赖。
