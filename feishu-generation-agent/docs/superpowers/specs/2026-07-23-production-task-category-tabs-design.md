# 生产任务分类选项卡设计

## 目标

将生产任务入口拆成“动画类”和“真人类”两个选项卡。每个选项卡只读取对应的飞书视图和需求类型，避免两类任务混在同一列表中，也避免误选后走错生成链路。

## 交互

- 页面默认选中“动画类”，首次进入时自动读取动画类任务。
- 用户首次切换到“真人类”时，自动读取真人类任务。
- 两个选项卡分别保留任务列表、加载状态和错误提示；来回切换时直接显示已读取结果，不重复请求飞书。
- 每个选项卡共用一个“刷新任务”按钮；点击后强制重新读取当前类别。
- 页面刷新后从默认的动画类重新开始，不需要跨页面持久化扫描结果。
- 最近完成任务继续作为全局列表展示，不按类别拆分。

## 视图与服务端隔离

- 动画类使用现有生产表及视图 `vewFRWT9ra`。
- 真人类使用同一生产表的视图 `vewvudainJ`。
- 浏览器通过固定类别标识请求任务，不直接提交任意飞书表格或视图 ID。
- 服务端维护“类别 → 视图 → 预期需求类型”的白名单映射：
  - `animation` → 动画视图 → `动画类`
  - `portrait` → 真人视图 → `真人类`
- 服务端读取指定视图后，再按记录中的“需求类型”做一次精确校验。视图中意外出现的其他类别不会返回到前端。
- 未知类别参数返回明确的参数错误，不回退到默认视图。

## 配置与兼容

- 现有生产表链接、表 ID 和动画视图配置继续兼容，动画类可沿用当前视图配置。
- 新增真人视图配置，默认使用当前已验证的真人视图 ID。
- 视图 ID 保持后端配置化，后续迁移主机、调整飞书视图或增加新类别时无需修改浏览器代码。
- 领取接口仍以记录 ID 工作；领取时继续重新读取并校验记录、状态、需求类型和锁，不依赖浏览器缓存判断。

## 负载控制

- 自动读取只发生在每个选项卡首次进入时，不进行后台轮询。
- 同一页面会话内反复切换选项卡不会重复访问飞书。
- 用户需要最新任务时通过“刷新任务”主动触发读取。
- 自动扫描只读取元数据和任务摘要，不读取需求文档、不上传资产，也不触发任何图片或视频生成费用。

## 错误处理

- 一个类别读取失败时，只在该选项卡显示错误，不清空另一个类别已经读取的列表。
- 配置缺少某个视图时，该类别显示明确的配置错误；另一类别仍可使用。
- 飞书视图与记录类型不一致时跳过不匹配记录，并保持其他有效记录可见。
- 切换期间禁用重复扫描当前类别，但不丢失另一个类别的缓存。

## 验收与测试

- 首次打开页面自动请求动画类，列表仅包含 `需求类型=动画类` 的未完成任务。
- 首次切到真人类自动请求真人类，列表仅包含 `需求类型=真人类` 的未完成任务。
- 来回切换不产生额外扫描请求；点击刷新只更新当前类别。
- 两个类别的加载、成功、空列表和错误状态互不覆盖。
- 服务端拒绝未知类别，并过滤视图中类型不匹配的记录。
- 领取、锁、审批、生成、重跑和统一结果表交付逻辑保持不变。
- 自动化测试不领取真实生产任务，不触发任何付费生成请求。
