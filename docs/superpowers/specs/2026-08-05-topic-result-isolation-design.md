# Seedance / Nano Banana 主题结果隔离设计

## 目标

保证 Seedance 和 Nano Banana 的每个主题页只展示该主题提交任务的实时进度、日志和生成结果。用户在任务提交中、运行中或完成后切换主题，都不能把结果写入或恢复到其他主题。

“生成历史”保持现有的用户级全局历史，不按主题过滤，也不改变管理员或普通用户现有的历史可见范围。

## 已确认的根因

1. 新建主题只重置表单和响应式状态，没有清空结果 DOM，因此会暂时保留上一主题的结果卡片。
2. `submit()` 发出请求后才调用 `pollJob()`；如果等待提交响应期间切换主题，轮询会把响应到达时的活动主题误认为任务所属主题。
3. 轮询请求每次动态读取当前活动主题，而不是固定使用提交时的主题 ID。
4. Seedance 的内存任务记录没有保存 `workspace_id`；活动记录调用也没有把主题 ID 传给 `record_activity()`，被默认值 `localhost` 覆盖。
5. 主题缓存允许保存任意 `_latestJob`，恢复时没有再次验证任务的 `workspace_id`。

上一次黑框闪烁修复只停止了对日志 DOM 的重复写入，没有改变上述主题归属流程。

## 设计

### 1. 固定任务所有者

用户点击提交时立即保存 `ownerWorkspaceId = activeTabId`。提交请求、轮询请求、状态更新、结果缓存和完成后的页面刷新都显式携带该 ID，不再在异步操作完成后读取当前活动主题。

提交过程中切换主题时：

- 原主题的 `submitting`、状态和结果更新写入原主题缓存；
- 当前主题不接收任何原任务内容；
- 切回原主题时恢复其最新状态和结果。

### 2. 后端保存并返回主题归属

Seedance 和 Nano Banana 的任务对象统一保存 `workspace_id`。任务详情和任务列表都返回该字段。Seedance 活动记录显式传入同一个主题 ID，避免被默认值覆盖。

任务详情接口按任务 ID返回数据时仍保留现有用户权限边界；前端另外校验返回任务的 `workspace_id` 是否等于轮询所有者。主题不匹配的响应视为隔离错误，不渲染、不写缓存，并停止该错误轮询。

### 3. 每个主题独立缓存

主题缓存以 `workspace_id` 为唯一键，分别保存：

- 提交状态；
- 进度文字；
- 事件日志；
- 最近一次属于该主题的任务快照；
- 当前主题表单及供应商状态。

保存缓存和恢复结果前都检查任务的 `workspace_id`。没有匹配任务快照的新主题必须显示空结果。

### 4. 新建和切换主题

新建主题后立即清空结果 DOM 和日志状态，且新主题缓存不继承 `_latestJob`。

切换主题时先保存离开主题的状态，再加载目标主题。目标缓存没有匹配结果时清空结果；有匹配结果时才重绘。

### 5. 用户级生成历史保持不变

Seedance 的“生成历史”继续展示当前用户的全局任务历史，不按活动主题过滤。主题隔离只约束实时结果区域、进度、日志和主题缓存。

## 防御性处理

- API 请求方法接受显式主题 ID，防止异步期间读取变化后的全局状态。
- 返回任务缺少 `workspace_id` 时，新任务轮询不允许渲染；历史兼容不受影响。
- 同一主题连续提交时，以最新提交任务为当前结果；旧任务完成后只能更新自己的后台状态，不能覆盖该主题较新的结果。
- 关闭主题后仍在运行的任务不得把结果写入当前其他主题；其缓存可在关闭时丢弃。

## 测试范围

自动化测试覆盖以下行为：

1. 新建主题立即清空上一主题结果。
2. 主题 A 提交后切到主题 B，A 的进度和结果只进入 A 缓存。
3. 提交请求尚未返回时切换主题，轮询仍绑定提交时的主题。
4. A、B 同时运行不同任务，来回切换只恢复各自结果。
5. 后端任务记录及 Seedance 活动记录保存正确的 `workspace_id`。
6. 返回任务主题与轮询所有者不匹配时拒绝渲染。
7. 用户级“生成历史”仍显示该用户的全局历史。
8. Nano Banana 和 Seedance 使用相同的隔离规则。

## 生效方式

前端改动在用户刷新页面后生效。Seedance 后端保存主题归属的改动需要重启服务；重启前必须确认所有运行任务已结束，因为任务状态保存在内存中。
