# Agent 参考素材理解与连续编号设计

日期：2026-07-27

## 目标

修复审批界面删除参考素材后编号不连续的问题，并让 DeepSeek 在生成
Seedance 任务 Plan 时真正理解参考素材，把素材的具体内容绑定到相应分镜。

完成标准：

1. 删除任意中间参考素材后，剩余素材立即按当前顺序显示为 `1…N`。
2. 传给 Seedance 的参考素材顺序始终连续，不会到执行阶段才因顺序错误失败。
3. Plan 中每个被引用的素材都有符合 Seedance 官方语法的语义绑定，例如
   `@图片1 中的黄铜毛毡空锅`，而不是只写“参考图片”。
4. 多分镜视频的每个镜头至少包含一个明确的素材引用或已定义主体引用。
5. 不合格的模型输出自动携带确定性校验错误重试，最多沿用现有三次修复机制。
6. 用户仍可在审批页面修改提示词、素材用途和顺序。

## 依据

采用用户提供的 Seedance 官方 SKILL 作为提示词规范，重点遵循：

- 图片、视频、音频分别使用 `@图片N`、`@视频N`、`@音频N`。
- 素材引用必须与具体主体、场景、动作、运镜或音色绑定。
- 复杂任务使用“总体绑定 + 镜头 1/2/3 + 约束包”的结构。
- 每个镜头使用强视觉指代，禁止裸露内部 Asset ID。
- 使用镜头顺序，不使用 `0–3 秒` 等绝对时间段。
- 默认包含画质、稳定、无水印、无 Logo 等必要约束。

## 已确认根因

### 编号问题

`unlink_reference` 当前只过滤被删除的 `asset_id`，保留其他
`ImageReference.order` 原值。参考素材校验只检查顺序是否重复，没有在编辑阶段
要求 `1…N` 连续，因此 `1、2、3` 删除 `2` 后会保存为 `1、3`。

### Plan 质量问题

当前规划系统提示词只规定任务类型、首尾帧模式和 JSON 格式，没有要求：

- 读取视觉描述后为每张素材建立语义名称；
- 在 prompt 中使用官方多模态引用语法；
- 每个分镜明确指出采用哪张素材；
- 禁止绝对秒数；
- 附加 Seedance 稳定性约束。

真实“火锅”Plan 证明该缺口：5 张参考图被结构化引用，但 prompt 的三个时间段
均未出现任何参考图绑定；删除图 2 后结构顺序还保留为 `1、3、4、5`。

## 方案

采用“模型规划 + 确定性校验和自动修复”的混合方案。

### 1. 参考顺序规范化

后端是顺序的唯一可信来源。每次执行以下变更后，都将引用按当前 `order`
排序并重建为连续的 `1…N`：

- 删除素材；
- 新增素材；
- 替换素材；
- 用户保存用途与顺序；
- 模型首次产生 Plan。

若用户提交重复、非正数或无法确定的顺序，仍返回明确校验错误，不猜测意图。
编号规范化在持久化 draft 前完成，前端轮询后自然显示新编号。

删除素材时，对提示词内可识别的官方引用做安全迁移：

- 存活素材的旧编号按资产身份迁移到新编号；
- 被删除素材的引用前缀移除，保留其后面的文字需求，避免把原素材语义错误绑定
  到另一张图；
- 使用临时占位符完成多编号替换，避免 `3→2` 后又被后续替换污染。

### 2. 素材语义理解

规划输入继续包含完整 `VisionDescription`，并新增不可覆盖的规划契约：

1. 逐张读取主体、场景、风格、构图、动作和用途描述。
2. 为每个实际引用生成简短且可区分的中文语义名称。
3. 结合文档结构、素材所在 block、同表格行、章节路径和视觉语义，判断素材适用
   的镜头。
4. 不得仅因素材存在就机械平均分配，也不得用“参考图片风格”这样的泛化措辞
   代替理解。
5. 没有适用镜头的素材必须进入 `excluded_assets` 并用中文说明原因，不能假装使用。

素材编号按传给供应商的实际内容顺序生成。图片、视频、音频在提示词中分别按类型
从 1 编号，结构中的 `order` 仍表示整个请求内容的稳定总顺序。

### 3. Seedance prompt 契约

简单单镜任务：

- 一段式提示词；
- 明确写出每个相关素材及其语义，例如
  `参考 @图片1 中的黄色毛毡火锅主体`。

复杂多分镜任务：

1. 第一段建立总体场景和素材定义。
2. 使用 `镜头 1`、`镜头 2`、`镜头 3`，不写绝对秒数。
3. 每个镜头至少直接出现一个 `@图片N`、`@视频N`、`@音频N`，或使用在第一段
   已明确绑定且本镜头可追溯的 `<主体N>` / `<场景N>`。
4. 每张被引用素材至少在一个实际镜头中发挥明确作用。
5. 末段加入风格、画质、稳定、文字、水印和 Logo 约束；多人或非写实场景按
   官方 SKILL 增加对应约束。

为提高可编辑性，Plan 保持中文主体，保留需求中明确要求的英文对白、品牌名和
界面文字。

### 4. 确定性校验与重试

在现有 `validate_plan` 中增加可自动测试的规则：

- 引用结构顺序必须为 `1…N`；
- prompt 不得包含内部 Asset ID；
- 每个结构化引用必须存在对应官方提示词 token；
- token 附近必须有非空语义描述，不能只是编号列表；
- 检测到多分镜时，每个镜头必须有可追溯素材绑定；
- 多分镜不得使用绝对秒数；
- 复杂视频必须含基本稳定性和无水印约束。

校验失败时复用现有三次 repair 流程，把具体缺失的素材和镜头反馈给 DeepSeek。
第三次仍失败则停止并显示规划校验错误，绝不让不合格 Plan 进入付费生成。

### 5. 兼容性

- 已保存的旧 Plan 继续可以展示。
- 用户编辑并保存参考素材时，会触发顺序规范化。
- 旧 Plan 只有在重新规划、重跑或再次审批校验时应用新的 Seedance 约束。
- Banana 图生图继续使用同一连续顺序机制，但不会套用 Seedance 的多分镜规则。
- 首尾帧模式仍必须恰好两张图片；多参考模式继续支持图片、视频和音频。

## 测试

先写失败测试并确认失败原因正确，再实现：

1. 删除 `1、2、3` 中的 `2`，结果为 `1、2`。
2. 删除首项和末项均得到连续编号。
3. 重新排序、上传和替换后仍连续且资产身份不变。
4. 提示词中的存活编号正确迁移，被删除素材不会错误指向另一素材。
5. “火锅”式三分镜、五图片 Plan 若缺少素材绑定，确定性校验失败并进入 repair。
6. 每个镜头均正确绑定素材的 Plan 通过。
7. 只在末尾列出素材编号、但镜头内未使用的 Plan 失败。
8. 混合图片、视频、音频分别产生正确 token。
9. 单镜图生视频、首尾帧和 Banana 图生图不被多分镜规则误伤。
10. 运行 Agent 后端、前端状态测试和 Portal 代理相关全量回归。

## 部署与验证

部署前检查是否存在正在付费生成的任务；只有安全时才重启 Agent，Portal 无需重启。
部署后用真实“火锅”需求重新规划但不批准付费生成，检查：

- 所有素材编号连续；
- 每张有效参考素材都有中文语义名称；
- 三个镜头均有明确素材绑定；
- 没有绝对秒数和裸 Asset ID；
- 提示词仍可由用户在审批界面修改。
