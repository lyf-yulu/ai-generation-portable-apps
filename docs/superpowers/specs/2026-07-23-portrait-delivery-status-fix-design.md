# 真人任务交付状态修复设计

## 背景

“茶壶青蛙”真人任务实际以 `completed_with_errors` 结束，没有生成产物或交付记录，但生产任务列表显示“已完成”。统一结果表同时保留了飞书创建多维表格时自动生成的 10 条空记录。

## 目标

1. 真人素材上传或 Asset 调用失败时保留正确的可重试错误类型，不再被不存在的枚举成员掩盖。
2. `completed_with_errors` 在生产任务列表中显示为失败，只有 `succeeded` 才显示完成。
3. 新建统一结果表后删除飞书自动创建、且字段完全为空的默认记录。
4. 安全清理当前统一结果表中已确认字段完全为空的 10 条记录。
5. 不自动重跑“茶壶青蛙”，避免产生未确认的生成费用。

## 设计

### 真人素材错误

统一使用现有的 `ErrorCategory.TRANSIENT` 表示临时网络或上游服务错误。`volcengine_portrait` 和 Seedance 音视频临时托管路径中的错误枚举一起修正，防止同一问题在多模态素材上复发。

### 生产状态

生产表同步时将 `completed_with_errors` 释放为 `TableTaskStatus.FAILED`。运行仍保留为可重跑的终态，前端通过现有失败状态展示，不新增状态或界面分支。

### 默认空记录

`FeishuClient` 增加读取和删除多维表格记录的明确接口。结果写入器在首次创建统一结果表并配置字段后，仅删除满足以下全部条件的记录：

- 响应中存在字符串 `record_id`；
- `fields` 是字典；
- `fields` 严格等于空字典。

含有任意字段的记录都不删除。现有结果表通过同一清理方法执行一次维护清理。

## 测试

- 模拟真人临时托管失败，断言抛出 `AgentError` 且类别为 `TRANSIENT`。
- 模拟 Seedance 参考音视频托管失败，断言错误类别为 `TRANSIENT`。
- 同步 `completed_with_errors` 运行，断言生产任务释放为失败。
- 新建结果表包含空记录和非空记录，断言只删除严格为空的记录。
- 运行完整 Python 测试套件和前端测试。

## 部署

修复在隔离工作区完成并合并回 `main`。重启前确认没有正在生成的任务；重启后检查 8765 服务、生产任务读取和结果表记录。用户随后可手动重跑“茶壶青蛙”。
