## 1. 身份校验 `portal_identity.py`

### 契约（已核实）

Portal 注入（`portal/app.py:2059-2084`）：

| 头 | 值 |
|---|---|
| `X-Username` | `urllib.parse.quote(username, safe="")` —— **percent-encoded** |
| `X-Portal-User-Id` | `str(user["user_id"])` |
| `X-Is-Admin` | `"1"`，仅管理员；非管理员**不发这个头** |
| `X-Portal-Ts` | `str(int(time.time()))` |
| `X-Portal-Sig` | `HMAC-SHA256(INTERNAL_TOKEN, f"{ts}:{'1' if is_admin else '0'}:{username_encoded}")` |

注意签名串里的 username 是**编码后**的值，`X-Portal-User-Id` **不参与签名**。

`INTERNAL_TOKEN` 由 Portal 启动时生成并写进 `os.environ`（`portal/app.py:125-126`），经 `start_app` 的 `os.environ.copy()`（`portal/app.py:613`）传给子应用。子应用读 `PORTAL_INTERNAL_TOKEN` 即可。

### 实现

抄现有范式 `nano-banana/app.py:128-145`，保持一致：

```python
import hashlib, hmac, os, time, urllib.parse

PORTAL_SIG_WINDOW = 60  # 秒，与 nano-banana 一致

def _token() -> str:
    return os.environ.get("PORTAL_INTERNAL_TOKEN", "")

def verify_portal_identity(headers) -> dict | None:
    """返回 {user_id, username, role} 或 None。headers 需支持 .get()（大小写不敏感）。"""
    token = _token()
    if not token:
        return None
    raw_user = headers.get("X-Username") or ""
    user_id = (headers.get("X-Portal-User-Id") or "").strip()
    is_admin = headers.get("X-Is-Admin") == "1"
    ts_raw = (headers.get("X-Portal-Ts") or "").strip()
    sig = (headers.get("X-Portal-Sig") or "").strip()
    if not raw_user or not user_id or not ts_raw.isdigit() or not sig:
        return None
    if abs(time.time() - int(ts_raw)) > PORTAL_SIG_WINDOW:
        return None
    msg = f"{ts_raw}:{'1' if is_admin else '0'}:{raw_user}".encode()
    expected = hmac.new(token.encode(), msg, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(expected, sig):
        return None
    return {
        "user_id": user_id,
        "username": urllib.parse.unquote(raw_user),
        "role": "admin" if is_admin else "user",
    }
```

**要点**：

- 签名用**原始的 `raw_user`**（编码态）拼串，`unquote` 只用于对外展示。搞反了必然验签失败。
- 角色只产出 `admin` / `user`。前端 `PortalSession.role` 接受 `admin|user|viewer`（`contracts.ts:2`），`viewer` 在 Portal 侧没有 `use_apps` 权限、根本到不了这里（`portal/app.py:1980` 拦截），所以不用处理。
- 时间窗 60s：Portal 每次代理都重新签，窗口内足够；机器时钟大幅漂移会导致全线 401，排查时先查 `date`。

### 中间件

```python
@app.middleware("http")
async def identity_boundary(request, call_next):
    if request.url.path.startswith("/api/"):
        user = verify_portal_identity(request.headers)
        if user is None:
            return JSONResponse(status_code=401, content={
                "code": "unauthorized", "message": "请通过 Portal 访问。",
                "retryable": False, "request_id": "identity", "phase": "authentication",
            })
        request.state.user = user
    return await call_next(request)
```

错误体形状照 `web/src/api/contracts.ts:19` 的 `ApiError`（`code/message/retryable/request_id/phase`），前端 `responseError()`（`client.ts:83-101`）能正确解析。

**不做 CSRF**：`X-CSRF-Token` 不在 Portal 转发白名单（`portal/app.py:2015-2020`），做了必然全挂。边界由「仅监听 127.0.0.1 + 签名头 + Portal 已鉴权」三者构成，与现有 5 个子应用同级。

**静态文件不校验身份**（路径不以 `/api/` 开头）：Portal 已经在代理层要求登录（`portal/app.py:1980` 检查 `use_apps`），子应用只监听回环，重复校验只会让 SPA 白屏难排查。

## 2. 会话 `GET /api/v1/session`

前端 `AuthGate`（`web/src/components/auth/auth-gate.tsx:14-28`）只要这个接口回 200 就放行，**零改动**即可接管登录。

响应形状 = `SessionResponse`（`contracts.ts:3`）：

```python
@router.get("/api/v1/session")
async def session(request: Request):
    u = request.state.user
    return {"user_id": u["user_id"], "username": u["username"], "role": u["role"]}
```

**关键约束**：`user_id` 必须稳定。它决定 IndexedDB 库名 `ai-creation-canvas:<env>:<userId>`（`web/src/storage/scope.ts:25-27`），变了用户本地画布就"消失"了（服务端副本还在，但本地草稿丢）。Portal 的 `user["user_id"]` 是持久 ID，直接用即可 —— **不要**用 username 代替（改名就丢数据）。

`csrf_token` 不返回。前端 `apiFetch` 见 `csrfToken` 为 null 就不发那个头（`client.ts:108`），正合适。

`must_change_password` 不返回（Portal 管密码）。

## 3. 存档 `store.py` + `/api/v1/projects`

### 数据模型

照搬 canvas 的表结构（`~/ai-creation-canvas/server/ai_creation_canvas/storage/sqlite.py:368-373`），这是全册唯一从它那儿"抄"的东西，因为形状确实合理：

```sql
CREATE TABLE IF NOT EXISTS canvas_projects (
    project_id  TEXT NOT NULL,
    user_id     TEXT NOT NULL,
    title       TEXT NOT NULL,
    document_json TEXT NOT NULL,
    version     INTEGER NOT NULL,
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL,
    PRIMARY KEY (user_id, project_id)
);
```

主键含 `user_id` → **归属隔离是结构性的**，查询忘带 user_id 会直接查不到而不是查到别人的。

连接设置（每连接执行）：

```python
db.execute("PRAGMA journal_mode=WAL")
db.execute("PRAGMA foreign_keys=ON")
db.execute("PRAGMA busy_timeout=5000")
```

WAL 是必须的：uvicorn 多 worker / 并发请求下没有 WAL 会频繁 `database is locked`。

用 `sqlite3` 标准库，**不引 SQLAlchemy**（仓库既有风格，且就两张表）。

### 接口

前端契约见 `web/src/api/projects.ts:9-17`。返回体一律是 `ProjectEnvelope = {project, version}`。

| 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|
| GET | `/api/v1/projects` | — | `{projects: [{project, version}, ...]}` |
| POST | `/api/v1/projects` | 整个 `CanvasProject` | `{project, version}` |
| GET | `/api/v1/projects/{id}` | — | `{project, version}` |
| PUT | `/api/v1/projects/{id}` | `CanvasProject` + `expected_version` | `{project, version}` |
| DELETE | `/api/v1/projects/{id}` | — | 204 |

`CanvasProject` 形状（`web/src/stores/canvas/use-canvas-store.ts:14-27`）：`{id, title, createdAt, updatedAt, nodes[], connections[], chatSessions[], activeChatId, backgroundMode, showImageInfo, viewport, graphSchemaVersion}`。

**服务端不解释文档内容**，整体当 JSON blob 存。只校验：

- `id` 匹配 `^[A-Za-z0-9_-]{1,128}$`
- `title` 长度 ≤ 200
- 序列化后 ≤ **1 MiB**（沿用 canvas 的 `_MAX_DOCUMENT_BYTES`，超了返回 413）
- `nodes` ≤ 1000、`connections` ≤ 2000（防止单个坏文档撑爆库）

### 乐观锁（必须实现，前端依赖它）

PUT 带 `expected_version`。UPDATE 时把它写进 WHERE：

```python
cur = db.execute(
    "UPDATE canvas_projects SET title=?, document_json=?, version=version+1, updated_at=? "
    "WHERE user_id=? AND project_id=? AND version=?",
    (title, doc_json, now, user_id, project_id, expected_version),
)
if cur.rowcount == 0:
    # 版本不匹配或项目不存在
    raise HTTPException(409, ...)  # code 必须是 PROJECT_CONFLICT
```

**`code` 必须精确等于 `PROJECT_CONFLICT`** —— 前端 `project-sync.ts` 靠它触发"冲突副本"分叉逻辑（`project-sync.ts:62-65,297`），拼错就变成普通错误，用户改动可能丢。

单条 UPDATE 带版本条件即为原子比较交换，不需要显式事务包读-改-写。

### POST 幂等

前端可能重试创建。若 `(user_id, project_id)` 已存在且文档相同，返回 **200 + 现有版本**而不是 409。真冲突（同 id 不同内容）才 409。

## 4. 素材 `/api/v1/assets`

用户拖图进画布 → 上传 → 拿 `asset_id` → 提交生成时按 id 引用。

### 上传 `POST /api/v1/assets`

前端用 XHR + FormData（`web/src/api/assets.ts:55-95`），字段：`kind`（恒为 `"reference"`）、`media_type`（`image|video|audio`）、`file`。

**响应字段前端逐个严格校验**（`assets.ts:14-36`），任何一项不符就抛「媒体上传响应无效」：

```json
{
  "asset_id": "<匹配 ^[A-Za-z0-9_-]{1,128}$>",
  "kind": "reference",
  "status": "active",
  "media_type": "image",
  "mime_type": "image/png",
  "size_bytes": 12345
}
```

硬性要求：
- `mime_type` 必须以 `"{media_type}/"` 开头（`assets.ts:23`）—— 服务端要自己推导，别直接信客户端的 `Content-Type`
- `size_bytes` 必须是 ≥1 的安全整数（`assets.ts:24`）—— 空文件要拒绝
- `status` 直接给 `"active"`（我们没有异步处理流程）
- **不要返回 `content_url`**，前端自己拼（`assets.ts:33`）

### 落盘

存 `infinite-canvas/state/uploads/<user_id>/<asset_id>.<ext>`，元数据入 `canvas_assets` 表（`asset_id, user_id, media_type, mime_type, size_bytes, path, created_at`，主键 `(user_id, asset_id)`）。

`asset_id` 用 `secrets.token_urlsafe(16)`。**绝不用客户端文件名做路径**（目录穿越）。扩展名由 mime 反查白名单得出，不认识就用 `.bin`。

大小上限：图 10MB / 视频 64MB / 音频 32MB（沿用 canvas 默认值）。注意 Portal 自身上限 200MB（`portal/app.py:1293`），我们的更严格，先命中我们的。

### 读取 `GET /api/v1/assets/{id}` 与 `/content`

- `GET /api/v1/assets/{id}` → 同上传响应的元数据形状
- `GET /api/v1/assets/{id}/content` → 文件字节，**必须支持 HTTP Range**

Range 是硬要求：`<video>` 元素要靠 Range 拿 metadata 才能画首帧（CLAUDE.md「Dreamina 前端格式双兼容」条目记过这个坑）。Portal 会转发 `Range`/`If-Range`（`portal/app.py:2016`）并且下行是真流式，链路没问题，就看我们实现。

FastAPI 用 `FileResponse` 即可自动处理 Range。手写要正确返回 `206` + `Content-Range` + `Accept-Ranges: bytes`，越界返 `416`。

- `DELETE /api/v1/assets/{id}` → 204，删库记录 + 删文件

**每个接口都必须带 `user_id` 条件查询**。asset_id 是随机的，但归属检查不能只靠"猜不到"。

## 6. 入口

### `app_fastapi.py`

```python
app = FastAPI()
# 中间件 + 各 router
app.mount("/", StaticFiles(directory="static", html=True), name="static")
```

**`app.mount("/")` 必须放在所有 API 路由注册之后** —— 挂在根上会吃掉后续所有未匹配路径。

SPA 回退：react-router 是 browser history 模式，刷新 `/canvas/abc` 会打到服务端。`StaticFiles(html=True)` 只对目录返回 `index.html`，不做任意路径回退。需要显式兜底：

```python
@app.get("/{path:path}")
async def spa_fallback(path: str):
    # 已被 StaticFiles 处理的不会到这
    return FileResponse("static/index.html")
```

安全：拼路径前必须拒绝 `..`、绝对路径、符号链接。或者更省事——只对 `Accept: text/html` 的请求回 `index.html`，其余 404。

### `app.py`（stdlib 回退位）

`portal/app.py:609` 要求 `<dir>/app.py` 存在，否则状态判 `missing` 根本不启动；`:646` 在 `engine != "fastapi"` 时回退跑它。写一个明确失败的占位，比让 Portal 静默跑起一个空壳强：

```python
import sys
sys.stderr.write("infinite-canvas 需要 FastAPI 引擎：请设置 INFINITE_CANVAS_ENGINE=fastapi\n")
sys.exit(1)
```

### 端口

uvicorn 由 Portal 用 `--port <config.port>` 启动（`portal/app.py:648-654`），**不读 `PORT` 环境变量**。但独立调试时要读，`app_fastapi.py` 里不用管，命令行给即可：

```bash
cd infinite-canvas
PORTAL_INTERNAL_TOKEN=devtoken ../.venv/bin/uvicorn app_fastapi:app --host 127.0.0.1 --port 8894
```

### 启动要快

Portal 看门狗每 15s 探活、连续 3 次失败即重启（`portal/app.py:685-715`），约 45s 窗口。启动路径**不要**做重活：不预热模型目录、不连子应用、不扫描上传目录。SQLite 建表很快，可以在启动做。

## 7. 验证

启动后（假设调试端口 8894）：

```bash
cd infinite-canvas
# 生成一组合法签名头
python3 - <<'EOF'
import hashlib, hmac, time, urllib.parse
tok, user = "devtoken", urllib.parse.quote("张三", safe="")
ts = str(int(time.time()))
sig = hmac.new(tok.encode(), f"{ts}:0:{user}".encode(), hashlib.sha256).hexdigest()
print(f'-H "X-Username: {user}" -H "X-Portal-User-Id: u-1" -H "X-Portal-Ts: {ts}" -H "X-Portal-Sig: {sig}"')
EOF
```

用输出的头依次验证：

| 检查 | 期望 |
|---|---|
| `GET /api/v1/session` 带正确头 | 200，`{"user_id":"u-1","username":"张三","role":"user"}`（中文正确还原） |
| `GET /api/v1/session` 无头 | 401，body 有 `code`/`message`/`phase` |
| `GET /api/v1/session` 篡改 sig | 401 |
| 把 ts 改成 200 秒前 | 401（时间窗生效） |
| `POST /api/v1/projects` 建项目 | 200/201，返回 `{project, version:1}` |
| `GET /api/v1/projects` | 列表含刚建的 |

| `PUT` 再次带 `expected_version: 1` | **409 且 `code == "PROJECT_CONFLICT"`** |
| 换一个 `X-Portal-User-Id` 后 GET 同 id | 404（归属隔离） |
| `POST /api/v1/assets` 传 PNG | 200，六个字段齐全且 `mime_type` 以 `image/` 开头 |
| `GET /api/v1/assets/{id}/content` 带 `Range: bytes=0-99` | **206** + `Content-Range` |
| 传 0 字节文件 | 拒绝（前端会校验 `size_bytes >= 1`） |
