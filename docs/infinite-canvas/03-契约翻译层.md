# 03 — 契约翻译层

**前置**：`00`~`02` 册
**产出**：`infinite-canvas/translate.py` + `/api/v1/models`、`/api/v1/jobs*`、`/api/v1/results/*`
**验证**：画布里点生成 → 出图/出视频 → 刷新页面结果仍在 → Portal 统计正确

---

## 0. 这一册要解决的问题

画布前端说一种话，我们的子应用说另一种话：

| | 画布 | nano-banana / seedance |
|---|---|---|
| 提交 | `POST /api/v1/jobs`，JSON，`{operation, model_id, prompt, params, asset_ids, inputs, idempotency_key}` | `POST /api/jobs/json`，JSON，扁平字段 `{prompt, model, provider, duration, ...}` |
| 素材 | 先传 `/api/v1/assets` 拿 id，再按 id 引用 | `media: {image_1: {data_url\|url}}` 内联 |
| 轮询 | `GET /api/v1/jobs/{id}` → `JobState` | `GET /api/jobs/{id}` → 原始 job dict |
| 结果 | `results[].{url, asset_id, media_type}` | nano-banana `results[].images[].download_url`；seedance `results[].download_url`（**形状不同**） |

翻译层坐在中间做双向映射，同时兼任 Portal 统计的上报口。

---

## 1. 一条不可妥协的约束：结果必须落自己的盘

**子应用的 `download_url` token 是进程内存态，重启即全部失效。**

- nano-banana 完全无持久化（`FILES` 是内存 dict，无 save/load）
- seedance 有 `state/download_files.json`，但 `load_files_map()` 只在 `main()` 里调用（`seedance/app.py:2657-2661`），而生产是 uvicorn 加载 `app_fastapi.py`，`main()` **永不执行**。更糟：重启后第一次 `save_files_map()` 会用内存里的新映射**覆盖**旧文件。

而画布会把结果地址**存进项目文档**（`web/src/services/api/video.ts:29`），文档是长期数据。存子应用 token → Portal 重启一次，所有历史画布的图和视频全部 404。

**做法**：任务终态时，翻译层立刻把结果字节抓回来，写进我们自己的 assets 存储（02 册的 `state/uploads/`），返回给画布的是**我们自己的稳定地址**。

抓取优先级：
1. `local_path`（两个子应用都在结果里给了服务器绝对路径）—— 同机直接读文件，零拷贝开销、不受 token 生死影响。**首选**。
2. `download_url` —— `local_path` 不可用时走 HTTP 兜底。
3. 都失败 → 任务标记 failed，`done` 如实报 0。**不要**假装成功。

> 顺带：这也让 01 册 §2.5「持久化存裸路径」自然成立——我们返回 `/api/v1/assets/{id}/content`，本来就是裸的。

## 2. 模型目录 `GET /api/v1/models`

### 数据来源

启动后（**懒加载**，别在启动路径做，看门狗只给 45s）请求：

- `http://127.0.0.1:8797/api/config` → nano-banana 的 providers/models
- `http://127.0.0.1:8787/api/config` → seedance 的 providers/models

缓存 60 秒。子应用没起来时返回空目录 + 记日志，**不要抛 500**（画布还能用来拖节点画草图）。

⚠️ **不要硬编码模型表**。两个子应用都有 `FALLBACK_PROVIDERS` 常量，且与 `providers.json` 实际内容**不一致**（nano-banana fallback 写的是 `nano-banana-2`，实际配置是 `gemini-3-pro-image`）。永远从 `/api/config` 读。

### 输出形状

`ModelSpec`（`web/src/api/contracts.ts:8-17`）：

```json
{
  "model_id": "nb:t8star:gemini-3-pro-image",
  "service_id": "nano-banana",
  "display_name": "Gemini 3 Pro Image (T8Star)",
  "operations": ["image.generate", "image.edit"],
  "input_media": ["text", "image"],
  "parameter_schema": { "...": "见下" },
  "input_ports": [
    {"port_id": "reference_images", "media_type": "image", "min_items": 0, "max_items": 14}
  ]
}
```

`model_id` 用 `<app缩写>:<provider>:<model>` 三段式，翻译回去时直接拆——**不要**另建映射表，多一份状态多一处不同步。

`operations` 映射：

| 子应用能力 | operations |
|---|---|
| nano-banana（图） | `image.generate` + `image.edit` |
| seedance（视频） | `video.generate` + `video.image_to_video` |

`input_ports.max_items` 按 provider 实测上限：nano-banana t8star/gemini = 14，volcengine(Seedream) = **10**（`nano-banana/app.py:1668-1671` 硬校验，超了任务直接失败）。seedance 参考图 = 9。

### parameter_schema 格式

必须是 `parameterControls()`（`web/src/components/model-picker.tsx:31-56`）认识的 JSON Schema 子集：

```json
{
  "type": "object",
  "properties": {
    "aspect_ratio": {"type": "string", "enum": ["auto","1:1","16:9","9:16"], "default": "auto", "title": "画幅"},
    "image_size":   {"type": "string", "enum": ["1K","1.5K","2K","4K"], "default": "2K", "title": "尺寸"},
    "repeat_count": {"type": "integer", "minimum": 1, "maximum": 50, "default": 1, "title": "生成数量"}
  },
  "required": []
}
```

支持的字段（其余一律被忽略）：`type` ∈ `string|number|integer|boolean`、`enum`、`default`、`minimum`、`maximum`、`title`、`description`、`x-ui-visible-when`。

**enum 校验很严**（`model-picker.tsx:40-42`）：enum 非空、元素类型一致、`default` 必须是 enum 中的值。任一不满足该控件被**静默丢弃**——参数不显示就查这里。

seedance 各模型的 `duration_range` / `resolutions` / `ratios` 直接翻成 enum 和 min/max。注意 `doubao-seedance-2-5-260628` 有 per-model `defaults: {"duration": 10}` 覆盖，要合进去。

## 3. 提交 `POST /api/v1/jobs`

### 路由

```
operation = image.generate | image.edit          → nano-banana 8797
operation = video.generate | video.image_to_video → seedance 8787
```

再由 `model_id` 的三段式拆出 provider 和真实 model 名。

### 一律用 JSON 端点

打 `POST /api/jobs/json`，**不要**用 multipart。原因（实测确认）：只有 JSON 路径会合并 `providers.json` 的默认值（`nano-banana/app.py:1250-1258` 的 `values_files_from_json` → `provider_defaults`），multipart 路径落到 handler 里的硬编码字面量，与实际配置不一致。

即便如此，**每个字段都显式发**，不依赖任何一侧的默认值。

### 字段映射

**nano-banana**（`VALUE_FIELDS` 见 `nano-banana/app.py:313-320`）：

| 画布 | nano-banana |
|---|---|
| `prompt` | `prompt` |
| model_id 第 2 段 | `provider` |
| model_id 第 3 段 | `model` |
| `operation == image.edit` | `mode: "img2img"`；`image.generate` → `"text2img"` |
| `params.aspect_ratio` / `image_size` / `response_format` / `seed` | 同名 |
| `params.repeat_count` | `repeat_count` |
| `asset_ids` / `inputs` | `media: {image_1..N: {data_url}}` |

⚠️ **`count = max(repeat_count, concurrency)`**（`nano-banana/app.py:1927-1930`，seedance 同）。想出 1 张就别把 `concurrency` 设成 4——会出 4 张并计费 4 张。翻译层**不要**透传 `concurrency`，固定发 1，只用 `repeat_count` 控制数量。

**seedance**（`VALUE_FIELDS` 见 `seedance/app.py:610-624`）：

| 画布 | seedance |
|---|---|
| `prompt` | `prompt` |
| model_id 第 3 段 | `model` |
| `params.duration` / `resolution` / `ratio` / `seed` / `generate_audio` / `watermark` | 同名 |
| `inputs.first_frame` | `media.first_frame` |
| `inputs.reference_images` | `media.ref_image_1..9` |

`provider` / `api_key` 发了也会被**丢弃并覆盖**（`seedance/app.py:2620-2630` 锁死 volcengine + 公司 Key），不用管。

**seedance 两条硬规则必须前置校验**（`seedance/app.py:1701-1705`，违反了是任务失败不是 HTTP 400，用户体验很差）：
1. `first_frame`/`last_frame` 与 `ref_*` **互斥**，二选一
2. `ref_audio_*` 必须搭配至少一个 `ref_image_*` 或 `ref_video_*`

翻译层在提交前检查，不满足直接返回 400 + 清晰中文 message。

### 素材传递用 data_url

画布的 `asset_ids` 指向我们自己存的文件。传给子应用有两条路：

- ✅ **`{"data_url": "data:image/png;base64,..."}`** —— 读本地文件转 base64 内联
- ❌ `{"url": "http://127.0.0.1:8893/..."}` —— 子应用会**服务端拉取**这个 URL，但我们的 assets 接口要求 Portal 签名头，它给不出；要放行就得开一个免鉴权端点，凭空增加攻击面

走 data_url。10MB 图片 base64 后约 13MB，回环传输可接受。

> seedance 拿到后会自己上传到火山 TOS 再给方舟（`seedance/app.py:1427-1455`）。注意这是**串行**的：9 张参考图 = 9 次连续 PUT，提交延迟会明显偏高，属正常。

### 调用时带的头

两个子应用都**不要求鉴权**（`GET /api/jobs/{id}` 完全无归属校验）。但要带：

| 头 | 值 | 作用 |
|---|---|---|
| `X-Username` | `urllib.parse.quote(username, safe="")` | 决定子应用侧输出目录 `outputs/<user>/<date>/`，也让子应用的任务列表按人分 |
| `X-Workspace-Id` | 固定 `infinite-canvas`（或按画布项目 id） | **必须给**。不给会落到 `localhost` 默认工作区，可能被无关的历史预设注入参考图 |

**不要**发 `X-Is-Admin`（没有有效签名会被忽略，发了是噪音）。**不要**发 `api_key`（子应用自己持有）。

### 响应

```python
return JSONResponse(
    content={"id": job_id, "operation": operation, "status": "queued"},
    headers={"X-Job-Id": job_id, "Access-Control-Expose-Headers": "X-Job-Id"},
)
```

三条统计硬要求（`04` 册 §3.2）：状态码 **200 或 201**（不能 202）、`X-Job-Id` 非空、路径已进白名单。

`job_id` 用**我们自己的 id**（不是子应用的），库里存映射 `{our_id → (app, upstream_job_id, operation, username, ...)}`。理由：子应用重启会丢任务，我们要能返回一个明确的 failed 而不是 404；而且 Portal 统计已经按我们的 id 登记了。

### 幂等

画布带 `idempotency_key`（`crypto.randomUUID()`，`use-generation-job.ts:107`）。同 key 重复提交返回**已存在的任务**，不重复下发——否则用户网络抖动一次就双倍计费。

## 4. 轮询

### 两个路由，一个 handler

| 路径 | 调用方 | 用途 |
|---|---|---|
| `GET /api/v1/jobs/{id}` | 画布前端 | `JobState` |
| `GET /api/jobs/{id}` | Portal 统计轮询（写死不带 `/v1`，`portal/app.py:987`） | 统计字段 |

同一 handler 挂两个路由，返回**并集**对象。两边各读各的，互不干扰。

### 响应形状

```json
{
  "id": "<our_id>",
  "operation": "image.generate",
  "status": "succeeded",
  "results": [{"url": "/api/v1/assets/AbC123/content", "asset_id": "AbC123", "media_type": "image"}],
  "result_url": "/api/v1/assets/AbC123/content",

  "done": 1,
  "total": 1,
  "task_type": "text2image",
  "duration": 0
}
```

上半段给画布（`JobState`，`contracts.ts:23`），下半段给 Portal 统计。

**`status` 只能是** `uploading|submitting|queued|running|succeeded|failed`（画布侧枚举）。而 Portal 认的终态是 `succeeded|failed|completed` —— 两者在 `succeeded`/`failed` 上重合，**用这两个即可同时满足**，不要引入 `completed`。

**`task_type` 决定统计分类**（`portal/app.py:1017-1022`），按 operation 映射：

| operation | task_type | 计入 |
|---|---|---|
| `image.generate` | `text2image` | 张 |
| `image.edit` | `image2image` | 张 |
| `video.generate` | `text2video` | 秒 |
| `video.image_to_video` | `image2video` | 秒 |

**`done` 必须是真实产出件数**。上游 3 成功 1 失败就报 3。纯失败报 0，**绝不 `max(1,...)` 兜底**（`portal/app.py:1003-1010` 明确警告会造幽灵计数）。

**`duration`** 只对视频有意义，报**每件**秒数。seedance 的 `results[].duration` 是实际时长，优先用它；缺失时用请求的 `duration`。Portal 算 `done * duration`。

### 上游结果的形状差异

**这是最容易写错的地方**——两个子应用结果结构不同：

```python
# nano-banana：嵌套在 images[] 里
for r in data.get("results", []):
    for img in r.get("images", []):
        img["download_url"], img["local_path"]

# seedance：平铺在 result 上
for r in data.get("results", []):
    r["download_url"], r["local_path"], r["duration"]
```

### 上游任务消失的处理

nano-banana `MAX_JOBS=500` + `JOB_PRUNE_GRACE_SECONDS=600`：完成 10 分钟后可能被清掉；重启则全丢。

轮询上游得 404 时：
- 我们已记录终态 → 返回已存的终态
- 未记录 → 标 `failed`，`done: 0`，message 说明「上游任务状态丢失」

**不要**因为上游 404 就无限重试。

### 摄取（ingest）

上游首次进入终态时，**同步完成**以下动作再对外报 succeeded：

1. 逐个结果取字节（优先 `local_path`，回退 `download_url`）
2. 写进我们的 assets（复用 02 册的存储，`kind: "reference"`, `status: "active"`）
3. 记录 `asset_id`，拼 `url = /api/v1/assets/{id}/content`（**裸路径**，见 01 册 §2.5）
4. 全部成功才置 `succeeded`；任一失败按实际成功数报 `done`，全失败报 `failed` + `done: 0`

摄取前的中间态对外报 `running`——画布的 `waitForJob` 会继续轮（1s 间隔，120s 上限，`jobs.ts:16-34`）。

> **注意画布前端的 120 秒上限**。视频生成常超过 2 分钟，`waitForJob` 会抛超时。但 `use-generation-job.ts` 有独立的重载恢复轮询逻辑，且我们的任务状态是服务端持久的，刷新页面能接上。如实测体验不佳，把 `maxWaitMs` 调大是前端一行的事——**先实测再改**，不要提前优化。

## 5. 取消 `POST /api/v1/jobs/{id}/cancel`

前端有这个调用（`jobs.ts:6`）。

⚠️ 这个路径是 POST 且命中 Portal 的 `/api/v1/jobs` 前缀白名单 → 会被当成创建任务。**响应绝不能带 `X-Job-Id` 头**，否则每点一次取消，统计就多记一个任务（`portal/app.py:2093-2097` 的三条件里，前两条它都满足）。

上游能力有限：Ark 只允许取消排队中的任务，运行中的不支持。做不到就返回当前状态，别假装成功。

## 6. 结果服务 `/api/v1/results/*`

摄取方案下，结果就是普通 asset，走 02 册已有的 `/api/v1/assets/{id}/content`（含 Range）。

`/api/v1/results/*` 可以不实现。若为兼容保留，做成到 assets 的 302 或内部复用同一 handler。**别再造一套 token 机制**——上游那套 token 的问题正是我们要摆脱的。
